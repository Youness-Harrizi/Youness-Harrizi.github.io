# Active Directory 101: Introduction and Fundamentals

*Understanding the Backbone of Windows Enterprise Networks*

---

## What is Active Directory?

<div class="key-concept" markdown="1">
Active Directory (AD) is a **hierarchical directory service** developed by Microsoft that stores information about objects on a network and makes this data available to users and administrators.
</div>

## Key Components

Active Directory consists of several essential components:

- **📁 Directory Structure** - Hierarchical organization of network resources
- **🔐 Authentication System** - Central authentication referential  
- **👥 Account Management** - Users, computers, and group management
- **📋 Policy Management** - Centralized configuration and security policies

---

## Core Terminology You Need to Know

Understanding these terms is crucial for working with Active Directory:

### 1. Fully Qualified Domain Name (FQDN)

```
W10-XXXXXXX.YYYY.ZZZZ
```

- The complete DNS name of a computer or domain
- Usually follows the forest structure for easier administration

### 2. Distinguished Name (DN)

```
CN=W10-XXXX,OU=France,OU=Computers,DC=company,DC=COM
```

- Unique identifier for each object in AD
- Composed of Relative Distinguished Names (RDN)
- Follows a hierarchical path structure

### 3. SAM Account Name

```
DOMAIN\W10-XXXXXX
```

- Traditional "login" format for AD objects
- Maximum 20 characters
- Used for both users and computers

### 4. User Principal Name (UPN)

```
username.lastname@domain.local
```

- Email-like format for user authentication
- Can be aligned with actual email addresses
- More user-friendly than SAM account names

## Security Fundamentals

### Security Principals

<div class="key-concept" markdown="1">
**Definition:** Any entity that can be authenticated by the system
</div>

Security principals include:
- **👤 Users**
- **💻 Computers** 
- **⚙️ Service accounts**
- **👥 Security groups**

### Security Identifiers (SIDs)

```
S-1-5-21-7623811015-3361044348-030300820-1013
```

Breaking down the SID structure:
- **S** - Indicates this is a SID
- **1** - Revision level (always 1)
- **5** - Identifier authority (always 5 for domain principals)
- **21-762...** - Domain identifier
- **1013** - Relative identifier (RID)

### Important RIDs to Remember

<div class="important-rids" markdown="1">
- **500** = Administrator
- **501** = Guest  
- **512** = Domain Admins
- **513** = Domain Users
</div>

## Active Directory Schema

<div class="key-concept" markdown="1">
The AD Schema is like a **blueprint** that defines what can exist in your Active Directory
</div>

### What Does the Schema Define?

- **🏗️ Object Classes** - Types of objects that can be created (users, computers, groups)
- **📝 Attributes** - Properties that objects can have (name, email, phone)
- **📏 Content Rules** - What attributes are required or optional

### Why Does the Schema Matter?

- Ensures consistency across the entire forest
- Defines what can and cannot exist in your AD
- **⚠️ Modifications affect the entire forest (be careful!)**

---

## Security Support Providers (SSP)

The authentication mechanisms Windows uses:

### Types of SSPs

- **🎫 Kerberos** - Primary authentication protocol (most secure)
- **🔒 NTLM** - Legacy authentication (less secure, but still widely used)
- **🌐 Digest** - For web-based authentication
- **🔄 Negotiate** - Automatically chooses between Kerberos and NTLM

### Why Should You Care About SSPs?

- Different protocols have different security implications
- Some attacks target specific protocols
- Understanding SSPs helps in hardening your environment
