# NTLM Relay: The Ultimate Man-in-the-Middle Attack

*Intercepting and Relaying Windows Authentication*

---

## 🔐 NTLM Authentication Flow

Before diving into attacks, let's understand the standard NTLM challenge-response mechanism:

<div class="key-concept" markdown="1">
**Standard NTLM Challenge-Response Process:**

1. **Negotiate:** Client says "I want to authenticate"
2. **Challenge:** Server responds "Here's a challenge: 4bcde133f44a68ca0"
3. **Authenticate:** Client replies "I am pixis and here's the encrypted challenge"
</div>

<div class="warning-box" markdown="1">
⚠️ **The Critical Flaw:** NTLM doesn't verify WHO is providing the challenge!
</div>

---

## 🎭 NTLM Relay Attack Concept

The NTLM relay attack exploits this fundamental weakness by positioning an attacker as a man-in-the-middle:

### Attack Flow

| Step | Action | Direction |
|------|--------|-----------|
| 1 | **Negotiate** | Client → Attacker |
| 2 | **Relay Negotiate** | Attacker → Server |
| 3 | **Challenge** | Server → Attacker |
| 4 | **Relay Challenge** | Attacker → Client |
| 5 | **Response** | Client → Attacker |
| 6 | **Relay Response** | Attacker → Server |

<div class="success-box" markdown="1">
🎯 **Result:** Attacker can now perform actions on the server with the client's privileges!
</div>

---

## 📋 NTLM Relay Prerequisites

### Required Conditions

1. **🕸️ MITM Position**
   - ARP poisoning, LLMNR/NBT-NS, IPv6 attacks, or coercion

2. **🚫 No SMB Signing**
   - Target must not require SMB message signing

3. **🔓 No Channel Binding**
   - LDAP/HTTP services without EPA protection

<div class="warning-box" markdown="1">
⚠️ **Key Limitation:** Cannot relay SMB to LDAP (except with CVE "Drop the MIC")
</div>

### Protocol Support Matrix

| Relay FROM | Relay TO |
|------------|----------|
| ✅ SMB (no signing) | ✅ SMB (no signing) |
| ✅ HTTP/HTTPS | ✅ LDAP/LDAPS |
| ✅ MSSQL | ✅ HTTP/HTTPS |

## 🌐 Cross-Protocol Relay Magic

The real power of NTLM relay comes from cross-protocol attacks:

<div class="key-concept" markdown="1">
**The Power of Protocol Independence**

Application layer (HTTP, SMB, SQL) is **independent** from authentication layer (NTLM, Kerberos)
</div>

### Common Cross-Protocol Scenarios

- **🌐 HTTP → LDAP:** Web authentication → Domain enumeration
- **📁 SMB → SMB:** File share → Admin share (lateral movement)
- **🗃️ MSSQL → LDAP:** Database authentication → AD queries

<div class="success-box" markdown="1">
🎯 **Ultimate Goal:** Turn any NTLM authentication into domain-wide access!
</div>

## 💥 CVE "Drop the MIC" (CVE-2019-1040)

This critical vulnerability changed the NTLM relay landscape:

<div class="vulnerability-alert" markdown="1">
**CVE-2019-1040: The Game Changer**

- **What it broke:** SMB → LDAP relay protection
- **How it works:** Removes MIC (Message Integrity Check) from NTLM authentication
- **Impact:** Enables SMB to LDAP relay attacks
</div>

### Attack Flow with Drop the MIC

1. **📁 SMB Auth** - Client connects to SMB
2. **🔧 Remove MIC** - Drop integrity check
3. **🗄️ LDAP Access** - Full AD enumeration

```bash
# ntlmrelayx with Drop the MIC
ntlmrelayx.py -t ldap://dc.domain.com --remove-mic --dump-adcs
```

<div class="warning-box" markdown="1">
🚨 **Modern Impact:** Many systems still vulnerable to this 2019 CVE!
</div>

## 🛠️ NTLM Relay Methodology

### 5-Step Attack Process

1. **🔍 Reconnaissance** - Identify targets without SMB signing
2. **📝 Generate Target List** - Use NetExec --gen-relay-list
3. **🚀 Launch ntlmrelayx** - Setup relay with target list
4. **🕸️ Position for MITM** - Responder, ARP poisoning, coercion
5. **💰 Profit** - Execute commands, dump secrets

### Essential Tools

| Tool | Purpose |
|------|---------|
| **ntlmrelayx.py** | Main relay tool |
| **Responder** | LLMNR/NBT-NS poisoning |
| **NetExec** | Target identification |
| **Coercer** | Authentication coercion |

### Attack Options

- `--dump-adcs` - Extract certificates
- `--dump-laps` - LAPS passwords
- `-c` - Execute commands
- `--socks` - SOCKS proxy

## 🛡️ Defense Strategies

### Primary Defenses

1. **Enable SMB Signing**
   ```powershell
   # Require SMB signing on all systems
   Set-SmbServerConfiguration -RequireSecuritySignature $true
   ```

2. **LDAP Channel Binding**
   - Enable LDAP EPA (Extended Protection for Authentication)
   - Configure channel binding requirements

3. **Network Segmentation**
   - Limit cross-protocol communication
   - Monitor authentication flows

### Detection Methods

- Monitor for unusual authentication patterns
- Watch for cross-protocol NTLM usage
- Detect authentication coercion attempts
- Alert on SMB signing mismatches
