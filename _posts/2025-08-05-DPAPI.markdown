# Active Directory 101: DPAPI (Data Protection API)
*Extracting Windows Secrets*

---

## What is DPAPI?

<div class="key-concept" markdown="1">
**DPAPI = Data Protection API**
</div>

The Data Protection API represents a Windows security feature that enables applications to store sensitive data through encrypted mechanisms. This system allows various applications to securely store sensitive information including passwords, certificates, and authentication tokens. The protected data resides in the user's directory, secured by encryption keys derived from the user's login password.

Storage occurs in a specific location: `C:\Users\$USER\AppData\Roaming\Microsoft\Protect\$SUID\$GUID`, where attackers focus their extraction efforts.

<div class="warning-box" markdown="1">
**Attacker Goal:** Extract and decrypt DPAPI-protected secrets to find passwords, tokens, and certificates!
</div>

---

## What Data Can We Extract?

DPAPI protection extends across a vast array of sensitive information, creating a treasure trove for attackers who successfully compromise these stores:

### Browser Data
Modern web browsers represent one of the richest sources of DPAPI-protected information. **Chrome and Edge credentials** include saved passwords and comprehensive login data that users accumulate over months or years of web browsing. **Cookies and session tokens** provide active authentication tokens that can maintain access to web services long after initial compromise. **Chrome refresh tokens** contain OAuth credentials that enable persistent access to cloud services. **Firefox saved passwords** offer another credential store, though Mozilla uses slightly different protection mechanisms. **Session data** encompasses active browser sessions that may include authenticated access to corporate resources.

### Network & System Data
Network-related credentials often prove invaluable for lateral movement within enterprise environments. **WiFi passwords** enable attackers to access wireless networks and potentially bypass network segmentation controls. **VNC credentials** provide remote desktop access to systems throughout the organization. **VPN configurations** may include authentication details that allow network boundary bypass. **Windows certificates** encompass both system and user certificates that can enable advanced authentication attacks. **Desktop files and recent document access** patterns reveal user behavior and potential high-value targets.

### Application Data
Specialized applications frequently store credentials through DPAPI mechanisms. **MobaXterm credentials** include SSH and terminal passwords that developers and administrators use for system access. **RDP saved passwords** provide remote desktop credentials for accessing servers and workstations. **SSH private keys** enable passwordless authentication to Linux systems and cloud infrastructure. **Recycle bin files** may contain deleted but recoverable sensitive data. **Cached credentials** from various applications provide backup access methods when primary authentication fails.

## DonPAPI - The Ultimate Tool

<div class="tool-showcase" markdown="1">
**DonPAPI: The Swiss Army Knife for DPAPI Extraction**

Automatically extracts and decrypts DPAPI-protected data from Windows systems
</div>

DonPAPI represents a comprehensive solution for DPAPI exploitation, providing automated extraction and analysis capabilities that streamline the credential harvesting process.

### DonPAPI Workflow

The tool operates through four distinct phases. First, it **scans** target systems to locate DPAPI blobs across various storage locations. Second, it **decrypts** discovered data using available user credentials and masterkeys. Third, it **parses** the decrypted information to extract readable passwords, tokens, and certificates. Finally, it **generates reports** in organized HTML format for efficient analysis.

## Certificate Extraction & Usage

### Certificate Attack Flow

The certificate exploitation process follows a systematic three-step approach. Initially, DonPAPI **finds and extracts** certificate files in .pfx format from protected storage locations. Subsequently, attackers **obtain Ticket Granting Tickets** using the extracted certificates for Kerberos authentication. Finally, they **extract NT hashes** from the authentication process, enabling additional attack vectors.

### Certificate Authentication

```bash
# Use extracted certificate for authentication
proxychains certipy auth -pfx '/home/auditor/.donpapi/loot/192.168.56.11/winterfell.north.sevenkingdoms.local_953B926BB18D96AB.pfx'
```

## DPAPI Attack Scenarios

### Corporate Espionage
Corporate espionage scenarios leverage DPAPI extraction to **steal saved passwords** from business applications and service accounts. Attackers **extract browser sessions** that maintain active connections to cloud services including Microsoft 365, AWS, and Azure platforms. This access often provides immediate entry into corporate cloud infrastructure without requiring additional authentication.

### Lateral Movement
Network expansion becomes possible through **WiFi credentials** that enable access to wireless networks and potentially bypass network segmentation controls. **RDP saved passwords** facilitate remote desktop access to additional systems throughout the organization. **VPN configurations** may include authentication details that allow attackers to tunnel past network boundaries and access internal resources.

### Certificate Abuse
Advanced attackers exploit **machine certificates** for system authentication and potential domain controller access. **Kerberos authentication** using extracted certificates enables access to domain services with machine-level privileges. **Domain privilege escalation** becomes possible when machine certificates provide pathways to administrative access across the Active Directory environment.

### Persistence
Long-term access maintenance utilizes **browser tokens** that remain valid for extended periods. **Long-lived sessions** provide persistent authentication to critical services. **Cached credentials** serve as backup access methods when primary authentication mechanisms are detected or blocked by security controls.

## Defense Strategies

<div class="warning-box" markdown="1">
**Defense Strategies:**

- **Enable Credential Guard** - Hardware-based credential protection
- **Use hardware-backed certificates** - TPM-based certificate storage
- **Implement proper endpoint protection** - EDR and behavioral monitoring
- **Monitor for unusual DPAPI access** - Detect bulk credential extraction
</div>

### Detection Methods

Security teams should monitor for mass DPAPI blob access patterns that indicate automated extraction tools. Watch for unusual certificate usage patterns that suggest compromised machine accounts. Detect browser credential database access that occurs outside normal user behavior. Alert on multiple authentication attempts using extracted credentials across different services.
